## 技术与边界

- 仅监听 127.0.0.1；Host / Origin 检查和每次启动生成的请求令牌限制浏览器跨站控制。
- Python 标准库 HTTP / SQLite，无第三方消息服务器；图片校验依赖 Pillow（本机已安装12.2.0）。
- `agents.py` 使用官方 ACP / App Server。2026-10-25已按用户要求解除纯文字限制，允许按任务使用Agent可用工具、读写文件和执行命令。Codex使用workspace-write沙箱和on-request审批；当前工作目录为本目录`public/room`。其他目录、网络等仍取决于原生权限与审批结果。
- 尚未验证长时间资源稳定性、Windows注销后运行、断电损坏恢复或自动重试；这是一版本机可用入口。
- Codex程序路径自动从显式覆盖、PATH或本机版本目录发现，避免更新后仍指向已删除的旧版本。
- 启动服务会懒加载两端进程，只有发送/继续才调用模型。自动交流使用模型额度，运行时可调间隔。

开发测试：在本目录执行 `python -m unittest test_room.py -v`（使用假agent，不调用模型）。实际模型联调应单独、少量执行。

### 用户确认的记忆规则

原生窗口用于单独聊天。每个角色使用各自同一个持久会话，群聊与单聊的记忆应双向连续：Codex记得自己的单聊，DeepSeek记得自己的单聊；单聊记录不自动广播给另一位AI，也不导入聊天室公开记录或导出文件。返回聊天室时重新恢复原会话，从而读取原生窗口保存的新内容。

群聊提示要求AI保留单聊记忆，但未经人类明确要求，不主动公开单聊具体内容。这是模型行为约束，不是对生成文字的绝对隐私隔离；群聊中实际发出的任何回答，另一位AI都能收到。范围为绑定的指定会话，不包括任意新建的原生对话。当前会话恢复代码已符合该方向；完整的原生单聊→群聊记忆实测仍待验收，不能用模拟测试代替。

目标是发送后4秒内显示实际回答。目前未达成稳定验收：简短OK测试low两次首字为3.013/2.772秒，而真实原会话记忆问答low首字为8.896秒。两者均从模型请求计时，不含进程恢复、前序排队和网页刷新。不能将这些值等同端到端首字时间，或承诺4秒上限。详见`延迟与双入口验证-2026-10-25.md`。

## 工具审批

Codex命令、文件改动和权限请求，以及Harness ACP `session/request_permission`，会在聊天室显示请求详情和审批按钮；不会再统一以“文字测试不支持”拒绝。允许只授予一次或本轮所列权限，不增加永久授权。未选择时等待，10分钟无回应拒绝；暂停、移交、插话或关闭服务会取消待审批请求。等待人类审批的时间不计入模型响应超时。

原生Agent自身允许的工作区操作可直接执行，无需聊天室为每次调用添加一次审批。此入口只转接两端已经提供的工具，不会自动获得当前Codex桌面聊天中所有插件的能力。暂未实现的结构化提问、MCP表单或动态工具协议会返回明确的不支持错误，Agent可改用公开回答向用户说明。

验证：`python -m unittest test_room.py test_approvals.py -v`，12项离线测试通过；JavaScript和Python语法检查通过。

## 2026-10-27 聊天室会话权限

聊天室“权限”下拉框可选择工作区访问或全盘访问（保留确认），保存在程序目录`room-access.json`，切换在下一轮连接时生效。Codex使用App Server的danger-full-access + on-request；Harness通过官方启动器`--patch`和权限预设服务，为本ACP进程恢复的绑定会话设置danger-full-access + ask。安装的Harness程序、其全局默认值、其他不相关原生对话均不修改。绑定会话的持久权限可能影响随后在原生应用里恢复同一会话。

## 2026-10-27 GPT 电量

侧栏显示“GPT 的电量”。通过官方Codex App Server的`account/rateLimits/read`读取当前订阅使用比例，以`100-usedPercent`显示每个周期的剩余电量；窗口名称由服务端实际`windowDurationMins`生成，支持五小时、七天和其他周期，不写死五小时。多种独立用量桶逐一显示，不相加或混成同一电量。主指示使用codex通用桶（唯一桶时使用该桶），取其所有有效窗口的最少余量；没有可确认的主桶则显示未知。
启动读取、每60秒刷新，Codex用量通知/回答结束会请求更新，也可手动刷新（15秒节流）。独立只读进程只初始化和读取账号用量，不恢复/创建会话、不调用模型，不读取或展示账号邮箱、账号ID、积分余额和重置券，不购买、不消耗任何重置权益。
余量≤20%时显示低电量，≤5%进一步提醒交接，0%或服务器明确阻止使用时显示不足。每次给两端投递上下文时加入允许公开的电量与恢复时间；低电量时提醒DeepSeek主动认领适合工作、Codex交接进展，避免重复实现。只提示分工，不擅自更改人类选择的模型或回复顺序，也不把这个提示当成额外的系统/账号操作授权。
读取失败、超过3分钟未更新、恢复时间已过但尚未获取新数据时明确标注上次读数/未知，不模拟充电，不自动回到100%。不估算剩余消息次数。这个电量是账号共享订阅窗口的快照，其他会话的使用也可能影响它，读取与下一次调用之间仍有时间差。
测试：test_battery.py与test_ui.js。来源：[官方Codex App Server用量接口](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。
